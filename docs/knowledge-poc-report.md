# B 知识服务 PoC 报告（迭代 1 前置探测）

> 日期：2026-11-14 · 版本：workbench 0.2.0 · 结论：**PoC 通过：可读、只读、证据链可信、召回率待迭代 2 解决**

## 1. 背景与目标

冻结 PRD 的迭代顺序为：迭代 1 = A 编排硬化，迭代 2 = B 知识接入。用户指令「继续」确认了本轮先做**知识服务 PoC**，用于在投入 A 硬化前先验证 B 的最大不确定性：现有知识库索引能否被外部只读复用、证据链能否可信落地。A 硬化顺延，顺序调整已回写 PRD。

PoC 目标（DoD）：

1. 探测真实知识库索引结构与规模；
2. 只读适配，不修改知识库任何字节；
3. 产出通过 `knowledge-card` 契约校验的知识卡；
4. 证据必须含本地路径、行号/页码、命中词；
5. 测试覆盖只读、越界、无命中不编造等边界；
6. 输出可执行的召回率改进决策。

## 5. 关键发现

1. **FTS 不可复用**，外部检索只能走 `documents` 元数据 + 正文扫描；
2. **元数据召回偏窄**：中文剧本文件名多为作品名/无名编号，不含「悬疑/反转」等主题词，导致 `screenplay` lane 候选为 0，最终证据全部来自 08 方法书；
3. **证据链可信**：路径、行号、片段、命中词四要素齐全，无法命中时状态回落 `no_evidence` 并明确禁止声称命中；
4. 现有 8 文件 py 工具与 APP 索引是**两套契约**（`curated-screenplay-methods.sqlite` vs `knowledgeIndex.sqlite`），本项目按后者适配，未触碰旧扫描链路。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 召回率低（尤其 05/06 剧本） | 用户觉得「查了但没参考到」 | 迭代 2 增加有限正文扫描回退，或按契约重建索引 |
| 行号≠书籍页码 | 用户按页码找原文有偏差 | 知识卡标注「行 N」并在 UI/文档说明；后续可选 PDF 页码映射 |
| 索引仅覆盖 15.7% 正文 | 大量文件仅元数据可用 | 与内容扫描回退策略配套评估 |
| 库根发现失败 | CLI 需显式 `--kb-root` | 已支持 env 与配置文件，doctor 可加检查 |
| 私有 tokenizer 变化 | 未来索引结构漂移 | 以 schema 指纹 + `issues` 上报，不静默失败 |

## 7. 迭代 2 决策建议（待用户确认）

- **方案 A（推荐，先做）**：有限正文扫描回退——对候选为空或不足的 lane，在分类目录内做有上限的文件名/正文抽样扫描，仍只读，成本可控；
- **方案 B**：按契约重建 `curated` 索引（需要 APP 协作或独立解析 PDF/DOCX），成本高、周期长，作为中期目标；
- 无论哪种，都保持「只有路径/页码/命中词齐全才可声称命中」的硬约束。
