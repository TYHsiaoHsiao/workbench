## 六、回滚演练（I4-05）

- 场景：旧项目经 `migrate` + `upgrade` 后，规则文件被替换；需要退回升级前版本。
- 做法：`upgrade` 在 `00_project/history/upgrade-<ts>/` 备份 `AGENTS.md`、`状态卡.md`、`00_project/routing.md`、`00_project/project-status.md`（扁平化命名）；把备份文件复制回原相对路径。
- 实测（`metrics.json → rollback_drill`）：
  - 备份目录 `upgrade-20261114-135930`；
  - `AGENTS.md`：还原后 SHA-256 前缀 `50875cfddda0`，与备份一致，且与升级后内容不同；
  - `00_project/project-status.md`：还原后与备份一致；
  - `ok = true`。
- 结论：备份可读、可还原、字节一致；回滚无需工具内反向操作，直接文件级恢复即可。

## 七、偏差与修复

1. `negative_checks` 在 `stage=done` 时直接调用门禁函数会 `KeyError: 未知阶段: 'done'` → 改为构造当前阶段/01 阶段克隆做负向验证，不落盘。
2. 试点 B 的「待处理门禁不能推进」检查最初用已通过的 05 门禁，未真正验证拦截 → 改为把当前阶段全部门禁置 `pending` 后再 `advance`，4/4 拦截。
3. 回滚演练最初找到错误的备份目录名 → 按 `upgrade-*`（`history/` 下）与扁平文件名还原，验证通过。
4. M2 原为硬编码「8 阶段」 → 改为按 `stage_artifacts` 实际记录与已执行阶段数（11）计算。

## 八、已知局限

- macOS 端 E2E 未实跑（路径与环境探测已有实现，逻辑与 Windows 共用）。
- 安装器只管理 Skill 目录树，不安装外部 Python 运行时。
- 参考记忆的 Markdown 视图在 JSON 变更后不自动重渲染（以 JSON 为唯一事实来源）。
- 迁移字段解析是启发式的，复杂旧格式需按 `migration-report.md` 人工核对。
- 知识服务召回仍受元数据与正文回退预算限制；完整召回仍需重建索引（方案 B，中期）。
- GitHub Actions 仅模板就绪，尚未推送远端实跑。
